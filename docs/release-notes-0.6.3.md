## 剪贴板酱 Clipchan 0.6.3

Windows 剪贴板历史工具。Ctrl+` 唤起面板，选中即粘贴回刚才那个窗口。
这一版不添功能，只补**出事时能不能救回来**：崩溃有日志、库坏了不丢数据、界面炸了不白屏、第一次打开知道该干什么。同时把许可与隐私摊开写清楚。

### 下载

- **安装版** `Clipchan-Setup-0.6.3.exe` — **推荐**。装到 `%LOCALAPPDATA%\Programs\Clipchan`，启动 0.3 秒级，可从「设置 → 应用」卸载。
- 免安装版 `Clipchan.exe` — 单文件双击即用，但**每次启动要等 20 秒以上**（自解压机制，原因见 0.6.2 的说明），只建议在不能安装的场合使用。

装过旧版的可以在「设置 → 版本与更新」里点「检查更新」自动升级。

### 崩溃有日志了

以前出问题时用户只能描述「它一闪就没了」，我这边什么都看不到。现在主进程会写 `%APPDATA%\Clipchan\logs\main.log`：

- 2 MB 轮转，最多留 5 份（`main.log` / `main.1.log` … `main.4.log`），不会无限长。
- 记录启动版本与数据目录、所有 `console.warn` / `console.error`、未捕获异常与未处理的 Promise 拒绝（含完整堆栈）。
- 渲染进程与子进程崩溃也记，带 `reason` 与 `exitCode`。
- **崩溃只记录、不退出。** 托盘常驻程序直接退出会抹掉用户手上的上下文，所以未捕获异常记完继续跑。
- 启动失败（库打不开、渲染文件缺失等）会弹一个明确的错误框，写清数据目录在哪、日志在哪，而不是静默死掉。

设置页「关于」里有「打开数据目录」，直达 `%APPDATA%\Clipchan`。

### 数据库损坏不再等于数据全丢

以前 `clipchan.db` 一旦损坏（断电、杀软误杀、磁盘坏道），程序在 `openDb` 抛错后直接崩，用户看到的是「双击没反应」。

现在启动时先做一次 `PRAGMA quick_check`（9 MB 的库约 18 毫秒）：

- 判定损坏就把原库改名成 `clipchan.corrupt-<时间戳>.db` 留在原目录（`-wal` / `-shm` 一并处理），再新建空库继续启动。
- 窗口加载完后弹一条提示，告诉用户备份文件名 —— 数据没删，只是挪开了，事后还能用 SQLite 工具抢救。
- 全新库会自动走一遍旧的 `history.json` 导入，老用户的迁移数据不会因为这次恢复而丢掉。

**为什么用 quick_check 而不是 integrity_check**：后者要逐页校验，几十万条记录要几秒，放在启动路径上不能接受。quick_check 抓的是结构级损坏，覆盖实际会遇到的绝大多数情况。

### 界面炸了不再白屏

主窗口与截图遮罩都套上了 ErrorBoundary。渲染层抛异常时不再是空白窗口，而是一句「界面出错了 · 这不影响你的剪贴板历史，重启后数据还在」，加两个按钮：

- **重新加载** —— 重载渲染进程，多数瞬时错误这一步就好了。
- **复制错误详情** —— 把版本、时间、UserAgent、错误名与堆栈拼成一段文本放进剪贴板，用户可以直接贴到 issue 里。

技术细节折叠在 `<details>` 里，不挡着正常使用。

### 第一次打开有引导了

历史为空、且停在「全部」分类、没在搜索时，空状态里会多出三条上手提示：复制任何东西 / 双击粘贴 / 按 Ctrl+Alt+S 截图标注。一旦库里有记录就永久不再出现，不会变成碍事的东西。

### 许可与隐私写清楚了

- 仓库根目录新增 **LICENSE**（MIT）。允许商用、修改、再分发，只需保留版权与许可声明。
- 新增 `docs/privacy.md`：数据存在哪（逐目录列表）、怎么彻底删干净、**整个程序只有三处联网**（OCR 语言包 / AI 优化 / 检查更新，各自触发条件、发什么、发给谁），以及如实写的边界 —— 本地数据不加密、排除列表按 exe 名匹配可能误伤、OCR 语言包依赖公共 CDN、AI 请求内容会离开本机。
- README 新增「隐私与许可」一节，设置页新增「关于」一节（版本 / 许可 / 隐私说明 / 打开数据目录 / 问题反馈）。

一句话：**没有账号、没有遥测、没有使用统计、没有崩溃上报、没有广告 SDK。**

### 数据兼容

老库直接打开，schema 未变（仍是 v3）。0.6.3 与 0.6.2 的库文件互相兼容。新增的只是 `logs\` 目录。

### 环境

Windows 10 / 11 x64。数据全部落在 `%APPDATA%\Clipchan\`。

### 已知边界

- **免安装版的启动时间没有本质改善**。340 MB 里 255 MB 是 Electron 本体，要秒开请装安装版。
- **日志不会自动上传**。出问题需要你手动把 `logs\main.log` 贴出来，没有一键上报（那需要服务器，与「零成本、纯本地」冲突）。
- **数据库恢复是「挪开 + 新建空库」，不是修复**。损坏库里的记录不会自动救回来，需要人工用 SQLite 工具导出。
- **富文本只保留原样的 HTML**，不做清洗与重排；粘贴到不支持 HTML 的地方自动退回纯文本。
- **拖出只支持图片与文件**，文本记录暂时不能拖出。
- 提权窗口因 UIPI 无法自动粘贴，会回退为「已复制，按 Ctrl+V 粘贴」。
- API Key 以明文存放在本地 `clipchan.db`，不加密。

详见仓库 README.md 与 docs/privacy.md。
