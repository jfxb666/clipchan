## 1. 三条铁律

★ **铁律一：截图 overlay 是独立渲染页面 `capture.html`，不是主窗口的一个 View。**
`View = 'list' | 'settings' | 'wordcloud' | 'optimize' | 'trash'` **不新增成员**。理由：overlay 要「每显示器一个全屏无边框置顶窗」，与主窗口的 900x620 圆角透明窗是两套完全不同的创建参数（`windows.ts:180-203` 那套参数只能在创建时定死），塞进同一个窗口既做不到也改不动。代价：多一个 Vite 入口 `capture.html` + 多一个 `CaptureOverlay` 挂载点。

★ **铁律二：底图是「先抓后铺」，不是「透明窗看桌面」。**
顺序必须是：按热键 → `desktopCapturer` 抓全部屏幕 → **然后**才建 overlay 窗把抓到的图当背景画。反过来（先建透明窗再抓）会把 overlay 自己拍进底图。这条不可调换。

★ **铁律三：OCR 引擎只在主进程跑，渲染进程只收文本。**
`tesseract.js` 是 CommonJS + worker_threads + WASM，渲染进程（Vite/browser 环境）跑不了。所有 `require('tesseract.js')` 必须留在 `packages/desktop/electron/` 下，渲染层只通过 `ClipchanApi.ocr` 拿结果。

### Rulings（计划期裁决，实施者不要再问）

- **Ruling 1**：热键字段名 `Settings.hotkeyCapture`，默认 `'Control+Alt+S'`。→ 与现有 `hotkeyActivate`/`hotkeyWidget` 同形；`HotkeyStatus` 同步加 `capture: boolean`。
- **Ruling 2**：OCR 语言固定 `['eng', 'chi_sim']`，不提供语言选择 UI。→ 用户要的是「中英文截图识别可用」；多做一套语言勾选是没提过的需求。
- **Ruling 3**：语言包下载源钉死 `https://cdn.jsdelivr.net/npm/@tesseract.js-data/<lang>/4.0.0_best_int/<lang>.traineddata.gz`。→ **实测**：tesseract.js 默认源 `tessdata.projectnaptha.com` 在本机直连超时，jsdelivr 可达。**禁止**用 `createWorker` 的默认 `langPath`。
- **Ruling 4**：语言包落 `<dataDir>/ocr/<lang>.traineddata.gz`，`langPath` 与 `cachePath` 都指这个目录；`corePath` 指 `tesseract.js-core` 的 **unpacked** 目录。→ 数据目录随 `resolveDataDir` 走，卸载重装不丢。
- **Ruling 5**：优化历史**由主进程在 `ai.optimize` 成功后自动写入**，渲染层不写。→ 渲染层若自己写，就会出现「复制走的文本」和「历史里的文本」两份真相；主进程手里才有最终的 `res.optimized`。
- **Ruling 6**：优化历史上限 100 条，超出淘汰最旧；入口是 `OptimizeViewCard` 内的抽屉，**不新增 View**（用户 m01069 拍板）。
- **Ruling 7**：OCR 结果「存为一条新记录」写 `kind='text'` 的普通记录，**不扩 `source` 枚举**（现只有 `'capture' | 'merge'`）。→ 加枚举要动 db 的 `sourceToDb/sourceToDto` 与全部迁移路径，收益为零。
- **Ruling 8**：标注工具集 = 矩形 / 箭头 / 自由笔刷 / 文字 / 马赛克 / 撤销重做 / 颜色。**不做**长截图、图层、水印、气泡（路线图 §P1 已定）。
- **Ruling 9**：`SCHEMA_VERSION` 1 → 2（新增 `optimize_history` 表）。

- `interface DisplayLike { id: number; bounds: {x,y,width,height}; scaleFactor: number }`

`CaptureOverlay.tsx`：
- 挂载时 `platform.capture.target(displayId)` 取底图（`displayId` 从 `location.search` 的 `?display=<id>` 读）。
- 底层 `<img src={dataUrl}>` 铺满（`absolute inset-0 w-full h-full object-fill select-none`，`draggable={false}`），上面一层 `<canvas>` 画标注，再上面一层半透明遮罩 + 选区挖空。
- 选区外区域用 `box-shadow: 0 0 0 9999px rgba(0,0,0,.45)` 的挖空技巧（不要用 4 个 div 拼）。
- 工具条：选区确定后浮在选区下方（空间不够翻到上方），按钮 = 5 个工具 + 6 个颜色 + 撤销 + 重做（用 `stack` 快照）+ 取消 + 完成。
- `完成` 时把 `<canvas>`（底图 + 标注）按选区裁剪成 PNG data URL，调 `platform.capture.finish({ displayId, pngDataUrl, action: 'copy' })`。
- 三个动作按钮：`复制`（默认，回车触发）/ `粘贴` / `存文件`。
- `Esc` → `platform.capture.cancel()`；右键 → 取消当前选区（有选区时）/ 取消截图（无选区时）。

### T4 · OCR 引擎（依赖 T1）

**只改这些文件**：新建 `packages/desktop/electron/ocr.ts` + `ocr.spec.ts`；改 `packages/desktop/electron-builder.yml`。

`ocr.ts` 设计（**依赖注入**，顶层不 import electron，与 `ai.ts` 同风格）：
```ts
export const OCR_LANGS = ['eng', 'chi_sim'] as const;
export const LANG_URL = (lang: string) => 'https://cdn.jsdelivr.net/npm/@tesseract.js-data/' + lang + '/4.0.0_best_int/' + lang + '.traineddata.gz';
/** 已实测的 SHA-256，写死在这里；对不上就拒绝使用该文件。 */
export const LANG_SHA256: Record<OcrLang, string> = {
  eng: '45b4cb346724ac1774f1c36f42f182b887bcdb28ebe63e6fff90ac41f3fcff91',
  chi_sim: 'b8a23f10c7de500891eb458a8adc9cc58ab7f242f08b7d149f5e9aea4ad5db7c',
};
export interface OcrDeps {
  langDir: string;          // <dataDir>/ocr
  corePath: string;         // tesseract.js-core 目录
  fetchBytes?: (url: string) => Promise<Uint8Array>;
  createWorker?: (langs: string[], opts: unknown) => Promise<WorkerLike>;
  onProgress?: (p: OcrProgress) => void;
  readFile?: (p: string) => Uint8Array;
  writeFile?: (p: string, b: Uint8Array) => void;
  exists?: (p: string) => boolean;
  sha256?: (b: Uint8Array) => string;
}
```
- `status(): Promise<OcrStatus>` —— 检查 `<langDir>/<lang>.traineddata.gz` 是否存在；两个都在 → `ready:true`。
- `download(): Promise<OcrStatus>` —— 逐个缺的语言包：`fetchBytes` → `sha256` 校验 → 不等则丢弃并回中文原因「语言包校验失败（<lang>）」→ 通过则 `writeFile`。**下载失败**回中文原因（超时/HTTP 状态/校验失败三类分开）。下载中通过 `onProgress({phase:'download', ratio, message})` 报告进度。
- `recognize(imagePath): Promise<OcrResult>` —— 懒创建 worker（`createWorker(['eng','chi_sim'], 1, { langPath, cachePath, corePath, gzip:true, logger })`），复用同一个 worker；`worker.recognize(path)` → `{ text: data.text.trim(), confidence: data.confidence, ms }`。**没就绪时抛中文错误**「尚未下载文字识别语言包」。
- `dispose(): Promise<void>` —— terminate worker。
- `<langDir>` 不存在时自动创建。

**实测数据（不要推翻）**：`createWorker` 从零起 worker 约 300–450ms，识别一张 640×160 图约 400–600ms；`corePath` 指向 `packages/desktop/node_modules/tesseract.js-core` 可用；`gzip: true` 配合 `.traineddata.gz` 文件名可用。

`electron-builder.yml`：`asarUnpack` 追加 `'**/tesseract.js-core/**'`（wasm 不能从 asar 里读）。

**约束**：不碰 `main.ts` / `channels.ts` / `types.ts` / `preload.ts`。单测**不许真的联网**——所有网络与文件 IO 都从 `OcrDeps` 注入假实现。

**验收**：`pnpm typecheck` 0 错误；`ocr.spec.ts` 覆盖：`status` 两个都在→ready / 缺一个→missing / 都缺；`download` 成功路径（校验通过 → 落盘 → status 变 ready）；`download` 校验失败路径（SHA 不对 → 不落盘 + 中文 error 含语言名）；`download` 网络失败路径（`fetchBytes` 抛错 → 中文 error）；`recognize` 未就绪时抛「尚未下载文字识别语言包」；`recognize` 成功路径返回 trim 后的文本。**这些用例必须能在完全离线时跑过**。

## 4. 全局约束

1. **不假装**：任何失败路径都要有中文原因，不许返回 `undefined` 假装成功（`ipc.ts:6-7` 的既有约束）。
2. **不加依赖**，除了已装的 `tesseract.js@^7.0.0`（T1 之前由调度者装好）。
3. **不新增 `View` 成员**（铁律一）。
4. 渲染层不许 `require` Node 模块；主进程模块顶层不 `import electron`（除非是 `overlay.ts` / `main.ts` 这类必须的）。
5. 组件文件与同名纯逻辑模块必须**不同名**（大小写不敏感文件系统的 TS1149，见 `OptimizeViewCard.tsx:23-29` 的既有教训）——所以是 `CaptureOverlay.tsx` + `captureOverlay.ts`（这两个只差大小写！）→ **改名**：纯逻辑模块叫 `captureOverlayLogic.ts`，组件叫 `CaptureOverlay.tsx`。同理 `ocrView.ts` + `OcrResultView.tsx` 不冲突（不同名）。
6. 中文注释与既有风格一致；注释解释「为什么」不解释「是什么」。
7. 每个 Task 一个 commit，message 用本文里写好的那句。
