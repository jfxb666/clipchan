## 1. 核心设计（改动前必须理解的三条）

### 1.1 软删 vs 硬删：两个家族，绝不混用

| 家族 | 语义 | 涉及 | 文件 |
| --- | --- | --- | --- |
| **软删**（进回收站） | `UPDATE items SET deleted_at = ?`，**不动磁盘** | `remove` / `removeMany` / `clearUnpinned` / `clearAll` / `evictOverLimit` | 保留 |
| **硬删**（purge） | `DELETE FROM items` + 删原图与缩略图 | `purge` / `purgeTrashOverLimit` / 图片预算淘汰 | 删盘 |

★ **图片预算淘汰必须走硬删**：`enforceImageBudget`（`packages/desktop/electron/images.ts:233-257`）的目的是腾磁盘。若改成软删，文件仍在，预算永远降不下来 —— 这是本计划最容易写错的一处。

★ **进站不删盘**是回收站的全部意义。`sweepOrphans`（`images-policy.ts:63-90`）只删「盘上有、库里没有」，回收站行仍在库里，所以文件天然安全，**该函数不需要改**。

### 1.2 唯一索引必须重建（SQLite 不能改谓词）

现状（`packages/desktop/electron/db.ts:59-60`）：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_content_hash ON items(content_hash) WHERE content_hash IS NOT NULL;
CREATE UNIQUE INDEX IF NOT EXISTS idx_image_hash   ON items(image_hash)   WHERE image_hash   IS NOT NULL;
```

软删后如果不改谓词，会连锁出两个 bug：

1. 去重查询 `SELECT id FROM items WHERE content_hash = ?`（`db.ts:429`）会命中**回收站里的行** → `touchRow` 刷新一条已删记录的 `created_at`/`seq` 并返回 `touched: true`，用户复制后列表里什么都不出现。
2. 若去重查询加了 `deleted_at IS NULL` 但索引没改，同内容再复制 → `INSERT` 撞唯一约束抛 `UNIQUE`。

**两处必须同时改**：去重 SELECT 加 `AND deleted_at IS NULL`，索引谓词改成 `WHERE content_hash IS NOT NULL AND deleted_at IS NULL`。

老库迁移：`ensureColumns`（`db.ts:628-641`）**只加列、不重建索引**，所以另起一段迁移，用 `PRAGMA user_version` 做版本号（全仓当前零使用，已确认 `grep user_version` 无命中）：

```
user_version 0 → 1：
  ALTER TABLE items ADD COLUMN deleted_at INTEGER;     -- 已有则跳过（PRAGMA table_info 判）
  ALTER TABLE items ADD COLUMN source_app TEXT;
  DROP INDEX IF EXISTS idx_content_hash;
  DROP INDEX IF EXISTS idx_image_hash;
  CREATE UNIQUE INDEX idx_content_hash ON items(content_hash) WHERE content_hash IS NOT NULL AND deleted_at IS NULL;
  CREATE UNIQUE INDEX idx_image_hash   ON items(image_hash)   WHERE image_hash   IS NOT NULL AND deleted_at IS NULL;
  PRAGMA user_version = 1;
```

`SCHEMA_SQL`（`db.ts:43-66`）同步改成新形态，保证全新库一步到位。迁移必须幂等（重复跑不报错）。

### 1.3 list / count 一致性

好消息：两者都走 `buildWhere`（`db.ts:295-311`；`list` 经 `buildListSql` `db.ts:313-326`，`count` 直接调）。**在 `buildWhere` 里加一条 `deleted_at IS NULL` 就同时修好两处**。不要分别改，那样才是「列表和共 N 条打架」的来源。

回收站自己的查询走独立方法，不复用 `buildWhere`（谓词相反）。

## 2. 数据结构变更

```ts
// packages/core/src/types.ts
export interface ClipItemDTO {
  // ... 现有字段不动
  /** 来源可执行文件名，如 "Code.exe"；未知时为 undefined（绝不写 "__unknown__" 这种兜底串）。 */
  sourceApp?: string;
  /** 在回收站里的时间戳；活跃记录为 undefined。 */
  deletedAt?: number;
}

export interface Settings {
  // ... 现有 9 字段不动
  /** 回收站上限（条）。超出后硬删最旧的回收站记录并删盘。 */
  trashLimit: number;
}
// DEFAULT_SETTINGS.trashLimit = 200
```

`Db` 接口（`db.ts:151-183`）新增：

```ts
listTrash(q?: { limit?: number; offset?: number }): ClipItemDTO[];
countTrash(): number;
restore(id: string): boolean;
restoreMany(ids: string[]): number;
/** 硬删指定行，返回实际删除条数。调用方负责先取图片相对路径再删文件。 */
purge(ids: string[]): number;
/** 硬删超出 trashLimit 的最旧回收站行，返回被删 id（供调用方删盘）。 */
purgeTrashOverLimit(): string[];
```

`InsertTextOpts` / `InsertImageOpts` 新增 `sourceApp?: string`。

★ `sanitizeSettings`（`db.ts:343-356`）白名单必须加 `trashLimit`（clamp 1–9999），漏了会**静默回默认值**。

★ 恢复时**保持原 `created_at` 与 `seq` 不变**，让记录回到原本的时间位置。安全性依据：`seq` 由 `MAX(seq)+1` 生成（`db.ts:198-200`），回收站行仍计入 `MAX`，所以不会撞号。

## 3. 任务书

### T1 · 数据库层：软删 + 迁移 + 回收站查询（阻塞其他全部）
- **边界**：`packages/desktop/electron/db.ts`、`db.spec.ts`、`packages/core/src/types.ts`（仅 Settings/ClipItemDTO/opts 字段）
- **要点**：§1.1–§1.3 全部；`evictOverLimit` 改为软删；`purgeTrashOverLimit` 用 `trashLimit`
- **验收**：① 老库（`user_version=0` 的 v0.2.0 库文件）打开后自动迁移且数据不丢；② 同内容「复制→删除→再复制」进列表且不抛 UNIQUE；③ `list`/`count` 对回收站行一致排除；④ 恢复后位置不变；⑤ `trashLimit` 生效；⑥ `pnpm test` 全绿且用例数 ≥ 501

### T2 · IPC 契约层：回收站五通道 + 设置项
- **边界**：`channels.ts`、`ipc.ts`、`preload.ts`、`types.ts`（`ClipchanApi`）、`ipc.spec.ts`、`preload.spec.ts`
- **通道**：`items:trashList`、`items:trashCount`、`items:restore`、`items:purge`、`items:emptyTrash`
- **要点**：★ 五处同步（`channels.ts` CH → `ALL_INVOKE_CHANNELS` → `ipc.ts` handler → `preload.ts` → `ClipchanApi`），漏一处就是运行时 `not-implemented`
- **验收**：`--smoke` 断言无遗漏；`preload.spec` 断言不暴露 raw `ipcRenderer`

### T3 · 图片与硬删路径：purge 才删盘
- **边界**：`images.ts`、`images-policy.ts`、`main.ts`（删除类 handler）、`images-policy.spec.ts`
- **要点**：`removeItemsWithFiles`/`clearUnpinnedWithFiles` 改为「软删 + 不删盘」；新增 `purgeItemsWithFiles`；`enforceImageBudget` 保持硬删并改用 purge；`planBudgetEviction` 排序改为**回收站行优先、然后最旧未收藏**
- **验收**：软删后文件仍在盘上；purge 后文件消失；预算淘汰仍能真正降盘

### T4 · zip 导出与导入
- **边界**：`main.ts`（exportAll/importAll）、`export-import.ts`（新建）、`channels.ts`+ipc/preload/types 的 importAll 通道、新增 spec
- **要点**：zip 含 `manifest.json`（`{app, version: 2, exportedAt, items}`）+ `images/` 原图；导入走 `dialog.showOpenDialog`，逐条校验、坏条跳过计数、单事务、重复 id/哈希跳过不整体回滚（对齐 `migrate.ts` 的既有风格）
- **依赖**：新增 `adm-zip`（同步 API、无原生编译）。理由：Node/Electron 均无内置 zip；手写 STORE 格式的读写约 250 行且易在中文文件名/大小写上出错
- **验收**：导出→删库→导入，条数与图片都回来；导入别人的包不覆盖现有数据
