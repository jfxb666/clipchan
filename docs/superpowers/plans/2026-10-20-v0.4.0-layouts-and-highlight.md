## 1. 核心设计（改动前必须理解的三条）

★ **铁律一：三视图是 list 视图内部的「布局模式」，不是新的 View。**
`View = 'list' | 'settings' | 'wordcloud' | 'optimize' | 'trash'` **不新增成员**。新增的是 `ListLayout = 'list' | 'timeline' | 'masonry' | 'source'`，它落在 `Settings.listLayout` 里持久化。类别筛选（`KindFilter`）与布局正交，可组合（「只看图片 + 瀑布流」）。
理由：`View` 驱动的是整页分支（`App.tsx:440/522/547/562/574`），把布局塞进去会逼着每个分支重写一遍；而布局只影响「同一批 items 怎么排」。错了的代价：若日后要按布局分页，得把 layout 提进 store 而非 Settings —— 改 3 处。

★ **铁律二：搜索词高亮与语法高亮互斥，有搜索词时只做搜索词高亮。**
`highlightSegments()` 已经在按 `term` 切 `<mark>`；再叠一层 hljs 的 HTML 会造成嵌套转义错误。规则：`term.trim() !== ''` → 走现有 `highlightSegments` 路径，完全不碰 hljs。
理由：正确性优先于「两者同时着色」这种低价值叠加。错了的代价：用户搜索代码时看不到语法色，可接受。

★ **铁律三：hljs 只渲染、不执行、不注入。**
必须用 `hljs.highlight(code, { language })` 返回的 `.value`（hljs 内部已对文本做 HTML 转义）喂给 `dangerouslySetInnerHTML`。**禁止** `innerHTML` 直接拼原文、禁止 `hljs.highlightAuto`（会加载全量语言包）。长文本超 `HIGHLIGHT_MAX_CHARS = 8000` 不做高亮。

### Rulings（计划期裁决，实施者不要再问）

- **Ruling 1**：字段名 `Settings.listLayout`，值域 `'list' | 'timeline' | 'masonry' | 'source'`，默认 `'list'`。— 与用户「默认仍是列表、首次升级行为不突变」一致；`'source'` 比 `'group'` 更能表达「按来源分组」。— 错了要改 types/db/spec 三处。
- **Ruling 2**：hljs 用 `highlight.js/lib/core` + 静态注册 13 种语言（含 sql），**不用** `highlightAuto`、**不用** 动态 import 分包。— renderer 是单文件 bundle，动态分包在 Electron 里只多一层异步竞态，没有收益；静态注册 13 种已经避免全量 190 种语言。— 错了要加语言只改一个数组。
- **Ruling 7**：SQL 文本归 `'sql'` 语言（剪贴板里 SQL 很常见），因此注册表是 13 种而非 12 种。— 用户需求里写的是「约 12 种」，13 在其范围内。— 错了少一种高亮。
- **Ruling 3**：布局切换器放 list 顶栏、SearchBar 右侧、「词云」按钮左侧，纯图标 4 个按钮（title 提示）。— 用户说「顶部加视图切换器」；900px 窗口下加文字会挤掉搜索框。— 错了挪位置只动 App.tsx 一段 JSX。
- **Ruling 4**：侧边栏优化入口放 `NAV_ITEMS` 之后、`<div className="flex-1" />` 之前（与「全部/文本/图片」并列），图标 `Sparkles`，点它调 `openOptimize('')`。— 用户明确说「与 全部/文本/图片 并列」；`OptimizeViewCard` 内部 `useState(restored?.input ?? source)` 在 `source === ''` 时照常可用（textarea 可手输），不需要伪造文本。— 错了只动 Sidebar.tsx。
- **Ruling 5**：瀑布流里的文本卡按行数估高，照常参与瀑布流。— 用户 m00138 第 5 条。— 无。
- **Ruling 6**：来源分组的组标签去掉 `.exe` 后缀（`Code.exe` → `Code`），未知来源显示「未知来源」并固定排最后。— 用户看到 exe 后缀没意义；DTO 里保留原名不丢信息。— 错了改一个纯函数。

`packages/desktop/electron/db.ts` `sanitizeSettings`（db.ts:400-414）追加一行，并在 `normalizeTheme` 旁新增归一函数：

/** 把任意输入归一化为四种布局（非法值回落 list）。 */
function normalizeLayout(v: unknown): Settings['listLayout'] {
  return v === 'timeline' || v === 'masonry' || v === 'source' ? v : 'list';

// sanitizeSettings 内：
listLayout: input.listLayout === undefined ? d.listLayout : normalizeLayout(input.listLayout),

### 2.2 `ClipItemDTO` 新增 `width` / `height`

瀑布流要按图片原始宽高比算列高。**数据库里 `width`/`height` 两列早已存在且已落库**（`db.ts:589` INSERT 列表含 width,height,bytes），只是 `rowToDto`（db.ts:274-307）没把它们放进 DTO —— **不需要任何迁移**。

```ts
export interface ClipItemDTO {
  // ...
  /** 图片原始宽高（v0.4.0 瀑布流算列高用）；非图片或无记录时 undefined。 */
  width?: number;
  height?: number;
}
```

`rowToDto` 图片分支里 `w` / `h` 已算出，只在 `w > 0 && h > 0` 时写进 DTO（沿用「有才给」的既有写法，不编 0）。

**新增模块 `codeHighlight.ts` 的公开面**（spec 直接 `import` 同目录文件，**不要**改 `ui/index.ts`）：

```ts
/** 超过该字数不渲染高亮，避免长文本拖慢列表。 */
export const HIGHLIGHT_MAX_CHARS = 8000;

/** 卡片里能高亮的语言（13 种，够覆盖剪贴板常见代码）。 */
export const HLJS_LANGUAGES: readonly string[];

/** 纯函数：按文本特征猜语言；猜不出返回 null。 */
export function guessLanguage(text: string): string | null;

/** 纯函数：是否该对该条渲染语法高亮。 */
export function shouldHighlight(kind: Kind, text: string, term: string): boolean;

/** 同步：返回 hljs 转义后的 HTML；调用前必须先 shouldHighlight 为 true。 */
export function highlightToHtml(text: string, language: string): string;
```

**测试先行**（`codeHighlight.spec.ts`）：

```ts
it('guessLanguage 认得出常见语言', () => {
  expect(guessLanguage('const a = 1;\nfunction f() {}')).toBe('javascript');
  expect(guessLanguage('def foo():\n    pass')).toBe('python');
  expect(guessLanguage('public class A { private void b() {} }')).toBe('java');
  expect(guessLanguage('SELECT * FROM t')).toBe('sql');
  expect(guessLanguage('随便一段中文，没有任何代码特征')).toBeNull();
});

it('shouldHighlight 的三条边界', () => {
  expect(shouldHighlight('code', 'const a = 1', '')).toBe(true);
  expect(shouldHighlight('text', 'const a = 1', '')).toBe(false);          // 非代码类不高亮
  expect(shouldHighlight('code', 'const a = 1', 'const')).toBe(false);     // 有搜索词时让位
  expect(shouldHighlight('code', 'x'.repeat(8001), '')).toBe(false);       // 超阈值不高亮
});

it('highlightToHtml 转义 HTML 特殊字符', () => {
  const html = highlightToHtml('<div>a && b</div>', 'xml');
  expect(html).not.toContain('<div>');
  expect(html).toContain('&lt;');
});
```

**语言判定实现要点**：复用 `logic/classify.ts` 的 `CODE_KEYWORDS` 思路，按特征串匹配：含 `def `/`import `+缩进 → python；含 `public `/`private `/`void ` → java；含 `interface `/`type `/`const `+`=>` → typescript；含 `fn `/`let mut `/`impl ` → rust；含 `func `+`package ` → go；含 `#include` → cpp；含 `using System` → csharp；含 `SELECT `/`select `+`FROM` → sql；`<?xml`/`<html` → xml；`{`+`:`+`;` → css；`#!/bin/` → bash；兜底 javascript；都认不出 → null。

**注册 13 种语言**（`highlight.js/lib/core` + 各自 `lib/languages/*`）：

```ts
export const HLJS_LANGUAGES = [
  'javascript', 'typescript', 'python', 'java', 'csharp', 'cpp', 'go',
  'rust', 'json', 'xml', 'css', 'bash', 'sql',
] as const;
```

★ 不变量：`guessLanguage` 只允许返回 `HLJS_LANGUAGES` 里的值或 `null`（有单测守）。`xml` 同时承担 html / xml / svg。
★ 若某个语言在 `highlight.js/lib/languages/` 下不存在，实施者必须换成存在的等价语言并同步 `HLJS_LANGUAGES` 与 spec，**不得留下注册不到的字符串**。

**ClipCard 渲染**：文本分支现在是

```tsx
{segments.map((segment, index) => segment.hit ? <mark .../> : <Fragment .../>)}
```

改成：`const html = shouldHighlight(item.kind, item.preview, term) ? highlightToHtml(item.preview, guessLanguage(item.preview) ?? 'javascript') : null;` 为 null 时走原 `segments` 路径，否则渲染 `<span className="cc-hljs" dangerouslySetInnerHTML={{ __html: html }} />`。`font-mono text-[12px]` 的 class 保持不变。

**TextViewer 渲染**：`<pre>` 分支同理加一层 —— 新增可选 prop `language?: string`（不传则按内容猜），`text` 非空且长度 ≤ `HIGHLIGHT_MAX_CHARS` 时渲染 `<code className="cc-hljs" dangerouslySetInnerHTML={{ __html: highlightToHtml(text, language ?? guessLanguage(text) ?? 'javascript') }} />`。**不要**给 TextViewer 传 `term`（浮层里没有搜索态）。
