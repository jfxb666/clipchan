## ① 本地加密 API Key（Windows DPAPI）

**做了什么**
- AI Key 落库前经 Electron `safeStorage` 加密（Windows 下底层就是 `CryptProtectData`，当前 Windows 用户作用域），存成 `enc:v1:<base64>`。
- 存量明文 Key 在**首次读取时就地加密**，幂等（第二次读不再写库）；迁移写回失败不致命，继续用明文。
- 系统加密不可用时**诚实降级**：存成 `plain:v1:<明文>` 并记一条 warn，不假装加密、不阻塞使用。
- 渲染层拿到的永远是掩码，明文只在主进程内存在。

**改动文件**
- 新增 `packages/desktop/electron/keyvault.ts`（129 行）：`ENC_PREFIX`/`PLAIN_PREFIX`、`needsSealing`、`createSecretBox(crypto)`、`createElectronSecretCrypto(safeStorage)`。纯模块，不 import electron，因此能在 node 下测。
- 新增 `packages/desktop/electron/keyvault.spec.ts`（18 用例）。
- 改 `packages/desktop/electron/ai.ts`：`AiDeps` 加可选 `secretBox`，`readKey` 三参化（读 → 解密 → 需要时写回），`saveProvider` 落库前 seal。
- 改 `packages/desktop/electron/ai.spec.ts`：原 19 条一字未改，新增 7 条（含「未注入 secretBox 时行为不变」「存量明文首次读取就地加密」「迁移幂等」「不可用降级」「解不开按未配置处理」）。
- 改 `packages/desktop/electron/main.ts`：`electronSecretCrypto()` 适配器 + `buildAiApi` 内注入 `createSecretBox`。

**验证**：keyvault.spec 18 通过、ai.spec 25 通过；typecheck 通过。

## ② 数据库自动备份 + 损坏自动恢复

**做了什么**
- 启动自检：`quick_check` 判定损坏时，**先从最近一份健康备份自动恢复**，恢复成功继续用；救不回来才走原来的「挪开 + 新建空库」兜底（兜底保留）。
- 自动备份：距上次备份超过 24 小时就备份一份，保留最近 7 份，文件 `backups/clipchan-YYYYMMDD-HHmmss.db`。
- 备份前先 `wal_checkpoint(TRUNCATE)`，写 `.tmp` 再 `rename`（原子），并 prune 旧备份。
- 恢复前先对备份文件跑 `quick_check`，并清掉 `-wal`/`-shm`，任一步失败则现库不动。
- 因为应用很少连续开满一天，用**每小时轮询 + 按备份目录最新时间戳判定**来补上关机期间欠的那份。

**改动文件**
- 新增 `packages/desktop/electron/backup.ts`（303 行）：`formatBackupStamp`/`backupFileName`/`listBackups`/`latestBackupTime`/`shouldBackup`/`isHealthyDb`/`createBackup`/`findLatestHealthyBackup`/`restoreBackup`。
- 新增 `packages/desktop/electron/backup.spec.ts`（21 用例，含真 WAL 端到端）。
- 新增 `packages/desktop/electron/storage-guard.ts`（159 行）：`recoverCorruptDb`（先找备份→恢复→失败才隔离）、`maybeBackup`（整函数 try，多备份无害、少备份致命）。
- 新增 `packages/desktop/electron/storage-guard.spec.ts`（15 用例，真 SQLite 文件）。
- 改 `packages/desktop/electron/paths.ts`：`BACKUPS_DIR_NAME` + `backupsDir()`（放在数据目录里，用户点「打开数据目录」就能看到）。
- 改 `packages/desktop/electron/main.ts`：`setupStorage` 接入 `recoverCorruptDb` + `maybeBackup`（checkpoint 用 `db.raw.pragma('wal_checkpoint(TRUNCATE)')`）；`BACKUP_POLL_MS` 每小时轮询；启动 toast 三分支（已从备份恢复 / 恢复失败已隔离 / 已隔离新建空库）。

## ⑧ 搜索升级（正则 / 布尔 / 时间范围）

**做了什么**
- 新增一套搜索语法，**原有三路（原文 / 全拼 / 首字母）一字未动**：
  - 空白 = 隐式 AND；`AND`/`&&`、`OR`/`||`、前缀 `NOT`/`!`；括号分组；`"a b"` 短语整体匹配。
  - 正则：`/pattern/flags`（flags 只认 i/u）或 `re:pattern`。
  - 时间：`after:2024-01-01`（本地 00:00:00.000）、`before:2024-12-31`（本地 23:59:59.999），也支持 `2024-12-31T18:00`。
- **纯词仍走原来那条三路 `LIKE`**，不经过解析器，性能与以前完全一致（`buildSearch` 里判「唯一 text 叶子且无时间条件」就折回 keyword）。
- 正则与布尔在应用层求值（先按普通条件取候选行再逐行匹配），因此能与类型 / 标签 / 文件夹 / 时间范围任意叠加。
- 刻意的宽容：`/usr/local/bin`、`a&&b` 按字面量搜（剪贴板里代码片段很多），正则只认「成对斜杠包起来的独立词」。
- 搜索框右侧按需出现「?」速查图标；写错正则/日期时出现警示图标，悬停显示原因。

**改动文件**

- 新增 `packages/core/src/logic/searchQuery.spec.ts`（64 用例）。

## ⑦ 链接 / 图片增强

**做了什么**
- **URL 预览**：复制公网 `http(s)` 链接后后台抓一次页面标题，卡片上显示「· 域名」，结果缓存 `url_previews` 表 7 天。
  - 只发一个普通 GET，**不带 UA / Referer / 任何本地数据**；内网地址（`localhost`/`10.x`/`192.168.x`/`172.16–31.x`/`.local`/纯 IPv6）**一个请求都不发**。
  - HTML 超 512KB **直接放弃不截断**（截断会解析出半截 `<title>`）；超时用 `Promise.race` 而不是只 abort（DNS 黑洞不 resolve）。
  - 站点图标只用链接自己主机的 `/favicon.ico`，**刻意不用任何第三方图标服务**（那等于泄露用户复制了哪些链接）。
- **图片相似去重**：采集时算 64 位 dHash 存 `items.phash`；入库前与最近 200 张图比汉明距离，≤10 判相似。**只提示不拦截**（「这张图库里已有一张很相似的，已照样保存」）——用户复制两次同一张图是常事，悄悄丢掉才是数据丢失。
- **二维码识别**：图片右键「识别二维码」，`jsqr` 纯 JS 解码，结果可复制或存为记录。三条失败路径（取不到像素 / 解码抛错 / 没找到码）一律返回空串，绝不抛给 IPC。

**改动文件**
- 新增 `packages/core/src/logic/urlPreview.ts`（254 行）+ spec（52 用例）；新增 `packages/desktop/electron/url-meta.ts`（119 行）+ spec（14 用例）。
- 新增 `packages/core/src/logic/phash.ts`（172 行）+ spec（44 用例）。
- 新增 `packages/desktop/electron/qrcode.ts`（196 行）+ spec（31 用例）；新增 `packages/core/src/ui/qrView.ts`（42 行）+ spec（15 用例）+ `QrResultView.tsx`（120 行）。

## ④ 包体瘦身 + 免装版提速

**做了什么**
- 剔掉**永不被加载**的 tesseract WASM 变体：`ocr.ts` 把 oem 固定传 1（`OEM.LSTM_ONLY`），`tesseract.js` 的 `getCore.js` 此时只 require `*-lstm` 三个变体，非 lstm 的 3 个 `.wasm`（9.88MB）+ 3 个 glue `.js` 是死重量。
- 剔掉 `tesseract.js` 的 `dist/` 与 `docs/`（`main` 指向 `src/index.js`，Node 分支从不读 dist）。
- 剔掉 `node-addon-api`（better-sqlite3 的依赖，但运行时只 require 预编译 `.node`，18 个 C++ 头文件纯死重量）。
- **不碰** Chromium 必需件（`Clipchan.exe` 195MB / `dxcompiler.dll` / `icudtl.dat` 等），也不动 asarUnpack / electronLanguages / win.target / portable / nsis 配置。

**改动文件**
- `packages/desktop/electron-builder.yml`（+25 行纯新增，10 条排除规则）。

**实测结果**

| | 改前（v0.6.3 配置） | 改后（v1.0.0） | 差值 |
|---|---|---|---|
| win-unpacked | 316,575,697 B / 301.9 MB / 66 文件 | 305,429,603 B / 291.3 MB / 60 文件 | **−10.6 MB / −6 文件** |
| app.asar | 5,467,695 B | 4,837,649 B | −0.63 MB |
| 安装包 | 81,256,843 B | 80,437,966 B | −0.82 MB |
| 免装版 | 80,809,328 B | 79,990,456 B | −0.82 MB |

- 免装版解压耗时（本机 7z 实测，多次测量）：v0.6.3 **3.1–3.6 秒** → v1.0.0 **3.1 秒**。解压时间只快一点点，真正收益是体积与文件数。README 里如实写了这一点，没有夸大成「启动快 6 倍」。
- 关于免装版 20 秒：根因是 `portable.nsi` **每次双击都全量解压整个 app 目录**，且第 38 行无条件先 `RMDir /r`。把 `unpackDirName` 固定成字符串也没用（还是先删再解）；`useZip: true` 会把 301MB 目录树塞进 exe（77MB → 200MB+），得不偿失。所以唯一真实的杠杆是**减小解压字节数**，也就是上面的瘦身。README 里把 20 秒的说明改成本机实测值 + 按体积比例放大。

**验证**：目录构建前后逐项核对（asar 列表 + 文件 SHA256）；三个 lstm 变体与 pnpm store 原文件 SHA256 完全一致；`better-sqlite3/prebuilds/win32-x64.node` 仍在。

## 已知边界（如实记录）

- 剪贴板历史本身仍然**不加密**（能读 `%APPDATA%` 的程序就能读到历史）；只有 AI Key 经 DPAPI 加密。
- 图片相似去重是**提示**不是拦截，阈值 10/64 是经验值，可能漏判（大幅裁剪/翻转后不算相似）。
- 链接预览只抓标题，不抓正文、不抓 og:image；抓不到就静默不显示。
- AI 助手的「停止」本版不可用。
- 应用层搜索的候选上限是 20000 行（正则/布尔搜索时），超出部分不参与匹配。

- 免安装版：双击 `release\Clipchan.exe`。它是个自解压包，会先解到 `%TEMP%\<随机串>\` 再启动，退出后自动删干净。
- ★ **两者共用单实例锁**：如果机器上已经装着旧版并在运行（`%LOCALAPPDATA%\Programs\Clipchan\Clipchan.exe`），先把托盘里的旧版退出，否则新启动的那个会直接把窗口让给已在运行的那个，看起来像「装了没生效」。

**构建耗时**：本机全量 `pnpm build` 约 5–6 分钟（vite 构建 + C# 助手 + 两次 electron-builder 出包），后台运行完成，`BUILD_EXIT=0`。
