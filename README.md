# 剪贴板酱 · Clipchan

Windows 剪贴板历史工具。Ctrl+` 唤起面板，选中即粘贴回刚才那个窗口。
Electron + React + SQLite，界面代码与手机端壳共用一份。

- **下载**：[Releases · v0.6.1](https://github.com/jfxb666/clipchan/releases/tag/v0.6.1)
  - **推荐**：安装版 `Clipchan-Setup-0.6.1.exe`（装完秒开，约 40MB 磁盘）
  - 免安装版 `Clipchan.exe`（单文件，双击即用，但**每次启动要等 20 秒以上**，原因见下）
  - ★ 免安装版慢不是程序的问题：它是个自解压包，每次双击都要先把 340MB 整个解到
    `%TEMP%\<随机串>\` 再启动，退出后还要删。机器越慢、杀软越勤，这一步越久。
    安装版把这些文件一次放到位，启动是 0.3 秒级。**只在不能安装的场合才用免安装版。**
- **源码**：本仓库（私有）。构建产物不进版本库，由 `pnpm build` 生成到 `release\`。

## 安装与首次运行

1. 从 Releases 下载 `Clipchan-Setup-0.6.1.exe` 安装并启动（免安装版 `Clipchan.exe` 每次双击都要先解压到临时目录，实测 20 秒以上，只建议在不能安装的场合使用）。
2. 托盘出现图标，按 **Ctrl+`** 唤出面板。
3. 面板出现在**鼠标所在显示器的中间偏上**，宽度 900、高度 620。

卸载安装版：从「设置 → 应用」卸载，或运行安装目录里的 `Uninstall Clipchan.exe`。

## 数据目录

一切落在 `%APPDATA%\Clipchan\`：

| 文件 | 内容 |
| --- | --- |
| `clipchan.db` | SQLite 库（历史记录 + 设置）。WAL 模式，强杀进程也不会整份丢历史 |
| `images\` | 原图（JPEG q80 或 PNG，长边 ≤ 2560） |
| `thumbs\` | 缩略图（PNG，长边 128） |
| `clipchan-export-<日期>-<时间>.zip` | 设置 → 数据 →「导出为 zip」写出并选位置的备份包（`manifest.json` + `images/` + `thumbs/`） |
| `history.json.migrated` | 旧版数据导入后的留档（改名即表示已迁移） |
| `settings.json` | 旧版设置文件。**新版只读不改**，设置存在 `clipchan.db` 里 |

从旧版升级：首次启动若发现 `history.json` 且库是空的，会自动导入全部记录并把文件改名为 `history.json.migrated`。旧文件的短键（`id/text/at/seq/pin/trunc`）与 C# 属性名两种写法都能认，认不出的单条跳过、不阻塞启动。

## 右键菜单与查看全文

在任意卡片上点右键，菜单从上到下是：**查看全文 / 查看大图**（图片、被截断的长文本才有）→ **识别文字**（图片才有）→ **复制到剪贴板**（只写剪贴板，不贴回原窗口，也不改动记录顺序）→ **复制并粘贴**（等于双击）→ **粘贴为纯文本**（图片没有）→ **优化提示词**（图片没有）→ **收藏** → **删除**。

长文本在列表里只显示前 200 字，库里最多存 10 万字；「查看全文」打开浮层看完整内容并可「复制全文」。图片卡片右键「查看大图」按原图分辨率显示，不是 64×64 缩略图。

搜索词在列表里会高亮命中片段。

## 排列方式与代码高亮

顶部搜索框右侧有四个图标按钮：**列表 / 时间轴 / 瀑布流 / 按来源**。它们只换「同一批记录怎么排」，不改变筛选内容——「只看图片 + 瀑布流」这种组合照常可用。选过的排列方式会记住。

- **时间轴**：按天分组、日期标题吸顶。今天 / 昨天 / 8月14日 / 2024年8月14日。
- **瀑布流**：按窗口宽度排 1–4 列，图片按真实宽高比显示。文本卡高度按行数估算，只用来决定放进哪一列。
- **按来源**：按复制来源的程序分组，组标题右侧标条数，组按「组内最新一条」倒序。来源名去掉 `.exe` 后缀；取不到来源的归到「未知来源」并固定排最后。

三种排列共用同一套分页：滚到底加载下一页，不是本地重排全部历史。回收站不支持这三种排列。

被判定为**代码**的文本记录会按语法着色（列表卡片与「查看全文」都有），支持 13 种语言：JavaScript / TypeScript / Python / Java / C# / C++ / Go / Rust / JSON / XML（含 HTML、SVG）/ CSS / Shell / SQL。语言按文本特征猜，猜不出就不高亮；超过 8000 字不高亮；**搜索时只有搜索词高亮**，两套着色不叠加。

## 文件记录

在资源管理器里复制文件，会被记成一条**文件记录**，卡片显示「文件 报告.pdf 等 3 个」。最多记 500 个文件。

- **只记路径，不复制内容。** 库里的 `file_paths` 是路径 JSON，原文件留在原处，不占额外磁盘；原文件被移走后粘贴会如实提示「文件已不在原位置」，不假装成功。
- **复制 / 粘贴会把真文件放回剪贴板。** 贴进资源管理器就是那批文件本身，不是一串路径字符串。写的是**标准 `CF_HDROP`**（见下文「为什么文件走原生助手」）。
- **绝对路径不出主进程。** 渲染层只拿到 `fileCount` 与「文件 a.txt 等 3 个」这样的摘要，界面上任何地方都不显示完整路径。
- **能按文件名搜**，拼音也能搜（见「搜索」）。
- 去重按路径列表整体算哈希：同一批文件重复复制不会重复记录，换顺序算同一批。

### 为什么文件走原生助手

Electron 37 的 `clipboard` 既读不出也写不出真正的 `CF_HDROP`：

- `clipboard.writeBuffer('FileNameW', buf)` 注册出来的是一个**自定义格式**（枚举 `EnumClipboardFormats` 实测 id **49159**、名字 `FileNameW`），`writeBuffer('CF_HDROP', buf)` 是另一个自定义格式（id **49962**）。两者都不是标准 format 15，资源管理器和别的程序一律读不到。
- 反过来，读别人写的 `CF_HDROP` 时 `has('FileNameW')` 返回 `true`，但 `readBuffer()` / `read()` 全空，`availableFormats()` 还会谎报 `text/uri-list`。

所以「有没有文件」问 Electron（`has()` 可靠），「有哪些文件」「把文件放进剪贴板」都交给 C# 助手走原生 `OpenClipboard` + `SetClipboardData(15, hGlobal)`。助手不可用时写回会退回 Electron 通道并如实报失败，不假装成功。

## 片段库

左侧栏的「片段」存常用文本：地址、签名、命令、回复模板。

- 每条有**标题**与**内容**；标题留空就用内容首行当名字。
- 点一下就**写进剪贴板并直接粘贴**回原窗口（与列表里双击同一条通道），同时「用过几次」+1，常用的自动排在前面。
- 上限 **200 条**；可改可删，删除是就地二次确认（3 秒窗口），不弹系统对话框。
- 存在本机 `clipchan.db` 的 `snippets` 表，不同步、不导出、不参与搜索。

## 搜索

搜索框同时匹配三条路：**原文**、**全拼**、**首字母**。

- 输入 `shougong` 或 `sgys` 都能找到「手工验收已完成」。
- 中英混排、数字、路径照常能搜；图片按「图片 1920×1080 · 320 KB」这种描述搜，文件按文件名搜。
- 命中片段在列表里高亮；**搜索时语法高亮让位**，只有搜索词高亮。
- 实现是给每条记录预建一列 `search_index`（原文 + 全拼 + 首字母，小写），用三路 `LIKE` 查 —— **不是 SQLite 的 FTS5**。原因：实测 FTS5 的 `trigram` 分词器对两字中文词完全不命中（`"验收"` / `"完成"` 都查不到），只能查三字以上，做中文搜索是废的。索引列在写入时生成，升级老库时会自动补建。

## 拖出到外部

图片记录与文件记录可以直接拖到别的程序：拖到资源管理器是导出文件，拖到聊天窗口是发图片。

- 只有 `image` 与 `files` 两类卡片带拖拽手柄（`draggable`）。文本记录不给拖，因为 Electron 的 `startDrag` 只认文件路径，拖文本得走 OLE `IDataObject`，本应用没有原生助手做这件事 —— 与其让人拖半天等一句"拖不出去"，不如一开始就不能拖。
- 浏览器默认的 HTML5 拖拽出不了窗口，所以卡片上的 `onDragStart` 只负责 `preventDefault()`，真正把文件交给系统的是主进程的 `webContents.startDrag`。
- ★ 这条通道走**单向 `send`，不是 `invoke`**。`DoDragDrop` 必须在 `dragstart` 的同步栈里发起，`invoke` 的异步往返会让 Chromium 先把这次拖拽收尾，主进程再拖就拖不出东西（表现：拖了没反应、也没有提示）。`ipc.ts` 里同一个通道名同时挂了 `on` 和 `handle` 两套，`preload` 用的是 `send`。
- ★ `startDrag` 的 payload 只在真有多文件时才带 `files` 键。Electron 的绑定先 `item.Get("files", &files)` 探键，键存在但值是 `undefined` 时转换失败会连带跳过 `file` 分支，同样表现为静默无反应。
- **多文件记录可以一次全拖**：Electron 的 `Item` 有 `files: string[]` 字段（它会覆盖 `file`），所以一次拖出整个文件列表。旧版本按"系统一次只能拖一个文件项"回绝多文件，那是错的。
- 拖之前会先用 `fs.existsSync` 过滤：原图被清理策略删掉、或文件记录指向的文件已经被用户在资源管理器里删掉时，不把不存在的路径交给 `startDrag`（它会抛在主进程里，异常既到不了界面也留不下提示），而是提示「这条记录没有可拖出的文件」。
- `startDrag` 会阻塞到拖放结束（内部是 Windows 的 `DoDragDrop` 模态循环），所以那一次 IPC 要等用户松开鼠标才返回 —— 拖拽期间主进程是停住的，这是 Electron 的既有行为，不是本应用卡了。

## 富文本保真

复制网页或 Office 里带格式的内容（加粗、列表、表格），粘贴到 Word / Excel / 邮件 / 飞书里**格式还在**。

- 采集时把 HTML 原样存进 `items.rich_html`（上限 20 万字符），粘贴时 `clipboard.write({ text, html })` 两种格式一起给。
- 目标程序只认纯文本（记事本、终端、代码编辑器）时，系统自动退回 `text`，不会变成一堆 HTML 源码。
- 只有 HTML 没有纯文本的复制（某些网页按钮），会存成一条占位文本「（富文本内容，无纯文本）」，不会丢。
- **HTML 原样保存，不做清洗与重排**。不执行其中的脚本（它只是一段字符串），但也不替你过滤样式。

### Word / Excel / PowerPoint 为什么需要特殊处理

Office 写剪贴板用的是 Windows 原生格式 `HTML Format`（CF_HTML），不是网页那套 `text/html`：

- `clipboard.readBuffer('text/html')` 对 Office 内容**恒返回空字节**，只有 `clipboard.readHTML()` 能拿到东西 —— 而它只给 `StartFragment` 到 `EndFragment` 之间的**片段**，把外层 `<style>` 全丢了。Excel 的表格样式全在那段 style 里，实测只写片段粘回 Excel 加粗会丢。
- 所以采集分三路，按优先级：① `readBuffer('HTML Format')` 按 CF_HTML 头里的字节偏移切出**完整文档**（`packages/desktop/electron/cfhtml.ts`）② `readHTML()` 拿片段 ③ `readBuffer('text/html')` 兜底。
- ★ CF_HTML 头里的 `StartHTML` / `EndHTML` 是**字节偏移不是字符偏移**，必须先切 `Buffer` 再解码，否则含中文时整段错位。

另一个坑：Office 复制时会**顺带写一份渲染位图**（`CF_METAFILEPICT` / `CF_ENHMETAFILE`），Electron 的 `readImage()` 能把它解成小图。不排除的话，Excel 复制 A1:B2 会被存成一张 145x39 的截图、PowerPoint 复制文字会被存成一张 423x105 的截图，文字全丢。

- 判据是「**有 image/* + 有 HTML + 有非空纯文本**」（`isRenderedPreview()`），命中就走文本分支。
- 刻意**不**用「拿不到图片字节」当判据：Excel 的 PNG 确实拿不到字节，但 PowerPoint 的能拿到 2510 字节，按字节判会漏掉 PowerPoint。

## 批量操作与粘贴为纯文本

选中多条（`Ctrl+点击` 或 `Shift+点击`）后底部出现操作栏：

- **批量粘贴**：按选中顺序用换行拼成一段写进剪贴板，图片记录会被跳过（图片没法拼进文本），超过 10 万字从头部截断。
- **批量收藏 / 取消收藏**：全都收藏了才显示「取消收藏」，混合选择按「收藏」处理。
- **批量删除**：进回收站，与单条删除同一条路径。

`Ctrl+Shift+V` = **粘贴为纯文本**：只贴文字，丢掉加粗、颜色、链接。从网页复制一段带样式的文字贴进代码编辑器时用这个。右键菜单里也有「粘贴为纯文本」。

## 按应用排除（隐私）

「设置 → 排除的应用」列出**永远不要记录**的程序，例如 `1Password.exe`、`KeePass.exe`。

- 从这些程序复制的内容**整条丢弃**：不落库、不出现在列表里、也搜不到。判断发生在写库之前，不是写完再隐藏。
- 填完整路径或只填 exe 名都行 —— 统一取文件名比较（不区分大小写、去引号），所以粘贴 `"C:\Program Files\1Password\1Password.exe"` 和填 `1Password.exe` 等价。
- 上限 50 条，附了几个常用密码管理器的快捷选项。
- 判断依据是复制那一刻的**前台进程 exe 名**；取不到前台进程时不会排除（宁可记下也不误丢）。

## 自动更新

「设置 → 版本与更新」里有「检查更新」按钮。

- 更新包从 **GitHub Releases** 下载，走 `electron-updater`，**不需要自建服务器**，也不上传任何本地数据。
- **启动时不自动检查**（避免每次开程序都打一次网络请求），只在设置页手动点。点过之后的状态会实时显示：检查中 / 已是最新 / 发现新版本 / 下载中（带百分比）/ 已下载（点「重启安装」生效）。
- 国内网络可能连不上 GitHub，此时如实报「检查更新失败，请稍后重试」，不影响正常使用。
- 开发模式（未打包）不检查，直接回「开发环境不检查更新」。

## 截图标注

按 **Ctrl+Alt+S**：屏幕被压暗，拖一个框开始标注。工具栏从左到右是五种工具（矩形 / 箭头 / 画笔 / 文字 / 马赛克）、换色、撤销，然后是三个去处（复制 / 粘贴 / 存文件）与取消。

- **先抓后铺**：热键按下时先把整个屏幕抓成底图，再建遮罩窗。顺序反过来会把遮罩自己拍进底图。
- **落库**：确认后那块选区会存成一条图片记录（来源标记为截图），同时默认复制到剪贴板。**复制前会抑制一次剪贴板监听**，否则这条记录会被再记一遍。
- **粘贴回原窗口**：走的是与列表里双击同一条粘贴通道，目标窗口失效时如实提示「已复制，按 Ctrl+V 粘贴」，不假装成功。
- **存文件**：弹系统保存对话框。取消对话框时**记录已经落库了**（这是有意的——你标了半天不该因为点错取消就白做）。
- **取消**：Esc 或右键。成功、取消、出错三条路径都会关掉遮罩窗，不会留下吃掉全部鼠标事件的全屏窗。
- **多显示器**：每个屏幕一个遮罩窗，抓图按各屏物理像素的最大值一次抓全（混合 DPI 时小屏会多抓像素，但不会糊）。
- 不做长截图、不做图层、不加水印与气泡。

## 文字识别（OCR）

图片记录右键「识别文字」。结果面板里可**一键复制**，也可**存为一条新记录**（写成普通文本记录，之后能被搜索到）。

- **引擎**：tesseract.js 7（WASM），跑在主进程。渲染层只拿文本，不碰 WASM。
- **语言**：固定中英文（`eng` + `chi_sim`），不做语言选择、不做翻译。
- **语言包**：首次使用要在「设置 → 文字识别」点下载，约 4.7MB，落在 `%APPDATA%\Clipchan\ocr\`。下载源钉死 jsdelivr（tesseract 的默认源 `tessdata.projectnaptha.com` 在本机实测直连超时），带 SHA-256 校验；非 2xx 会单独报「服务器返回错误」，连不上报另一句，不把错误页当语言包写进磁盘。
- **识别前会自动放大**：屏幕截图里的正文通常只有 12–14px，直接喂给引擎错字率很高。程序会把图放大 4 倍（放大后短边不超过 2000px）再识别，并把分页模式固定为「单块文字」。
- **识别后清理文本**：tesseract 会在每个汉字之间插空格（`出 在 做 的 事`），程序会把两个汉字之间的空格删掉，中英文之间的空格保留。

## 回收站与撤销

删掉的记录**不会立刻消失**：`Delete`、右键删除、清空未收藏、以及超出「历史上限」被淘汰的记录，都先进**回收站**（左侧栏底部的「回收站」），原图与缩略图原样留在盘上。

- **撤销**：删除后提示条上有「撤销」，3 秒内也可以按 `Ctrl+Z`（搜索框聚焦时不抢）。撤销就是把刚才那批 id 逐条从回收站恢复。
- **恢复**：回收站里逐条点「恢复」，记录回到**原来的时间位置**（`created_at` 与 `seq` 都不变），不是回到最顶上。
- **同内容冲突**：如果删掉之后又复制了同样一段内容，那条已经在列表里了，此时恢复会失败并提示「同内容已在列表中，无需恢复」—— 不会覆盖你新复制的那条。
- **永久删除 / 清空回收站**：这两条**真删盘**，无法撤销，所以都要点两次（3 秒窗口）。回收站有自己的上限（设置 → 数据 →「回收站上限」，默认 200），超出的按最旧淘汰、同样删盘。

回收站**不参与搜索和分类**：它是独立视图，只有分页浏览。

## 导入导出

「设置 → 数据」里有「导出为 zip」和「导入备份包」：

- **导出**：弹系统保存对话框选位置，包内是 `manifest.json` + `images/`（原图）+ `thumbs/`（缩略图）。只导活跃记录，**不含回收站内容**。原图文件丢了的条目照样导出，只是该条没有图（提示里会报「缺图 N 条」）。
- **导入**：弹系统打开对话框选 zip，是**加法不覆盖** —— 重复 id、重复内容哈希、重复图片哈希一律跳过，不会改动你现有的任何一条。坏条目跳过并计数，好的照进；整批在一个事务里，中途失败回滚并清理已落盘的文件。
- 导入**不触发**「历史上限」淘汰：悄悄把你刚导进来的记录踢进回收站比超限更糟，超出的部分靠后续正常复制自然收敛。

## AI 提示词优化

选中一条记录，点卡片右侧的「优化提示词」→ 选场景与模式 → 点「优化」→ 左右分栏对比原文与结果（结果边生成边显示，可随手改）→ 「复制」只写剪贴板，「直接粘贴」才贴回原窗口。优化由你自己配置的模型完成；场景与方法论是编译进程序的固定数据，运行时不联网取规则。

完整路径：**设置 → AI 模型 → 添加模型**（填名称 / 协议 / Base URL / API Key / 模型名 → 保存）→「发送测试消息」验证连通 → 回到列表点卡片右侧「优化」→ 选场景与模式 → 优化 → 看结果与补充说明 → 复制或直接粘贴。

### 三种协议的 Base URL 怎么填

| 协议 | Base URL 填什么 | 说明 |
| --- | --- | --- |
| OpenAI 兼容 | `https://api.openai.com/v1`，或只填到域名 `https://api.openai.com` | 程序会去掉末尾多余斜杠；路径里没有 `/v1` 这类版本段时自动补 `/v1`。中转站填它给你的地址 |
| Anthropic | `https://api.anthropic.com` | 程序按协议补 `/v1` |
| Gemini | `https://generativelanguage.googleapis.com` | 程序按协议补 `/v1beta` |

填的地址不是完整链接（例如漏了 `https://`）会被当场拦下并提示，不会拿一个半成品去发请求。

「发送测试消息」通过会显示模型可用，不通给中文原因：鉴权失败 / 网络连接失败 / 请求超时 / 请求过于频繁 / 模型返回格式异常。
「拉取列表」在部分中转站、以及 Gemini 原生路径下可能失败 —— 这不是 bug，**直接手输模型名即可**，不影响使用。
Key 只在主进程读取，界面上只回显掩码（`sk-…abcd`）；编辑已有模型时 Key 留空表示不修改。

### 四类场景各适合什么

| 场景 | 适合 |
| --- | --- |
| 通用对话 | 对 AI 提需求、问问题，把随手写的诉求补成一条能直接用的提示词 |
| AI 生成 | 文生图 / 文生视频 / 音乐等创作，把一句想法补成可复现的生成提示词 |
| 产品·项目描述 | 写产品介绍、项目说明、需求文档，把形容词换成能验证的事实 |
| 日常交流 | 跟朋友聊、发消息、回邮件，改写成你自己会发出去的那句话 |

### 两种模式的区别

| 模式 | 产出什么 | 什么时候用 |
| --- | --- | --- |
| 用户提示词 | 一条能直接发给 AI 的提示词：保留原意，补上角色与目标、上下文、输出格式与长度、约束条件 | 你要问 AI 一件事、要一段内容或一次生成 |
| 系统提示词 | 一份角色 / 约束型 system prompt：按角色身份、能力边界、输出规范、拒答策略四块组织，写成对 AI 的第二人称指令 | 你要给某个 AI 应用或助手定人设与规矩 |

两种模式用的是两套不同模板，不是把同一段文字换个标题。

### 优化历史

优化面板右上角有「历史」按钮，打开后盖在结果栏上。

- 每次优化**成功后由主进程自动写入**（渲染层不写，否则「复制走的文本」与「历史里的文本」会有两份真相）。
- 每条存：**原文 + 结果全文 + 场景 + 模式 + 模型 + 时间**。
- 上限 **100 条**，超出按时间淘汰最旧的。
- 点任意一条 → 原文与结果直接填回面板，不用重跑。
- 可单条删除，也可一键清空（清空前就地二次确认）。
- 历史存在本机 `clipchan.db` 的 `optimize_history` 表，不同步、不导出。

### 能力边界（如实写）

- **优化质量取决于你选的模型。** 同一个场景换模型，结果差别可能很大；程序只负责把方法论和原文拼成一次请求，不联网取规则。
- **API Key 以明文存放在本地 `clipchan.db` 里，本轮不做加密。** Key 只在本机被读取、只发给你填的那个接口地址，不上传到别处；但共享电脑上任何人拿到该文件就等于拿到 Key，需自行注意。
- **流式输出，超时按块算。** 优化期间结果区逐段增长；超时不是整段 60 秒，而是「首块 30 秒 / 块间 60 秒」——只要模型还在吐字就一直等，实测 20 秒才出首字的慢模型也能正常完成。按钮在请求期间禁用，超时给中文提示、按钮恢复可点。不做多轮自动迭代优化（生成-批判-自进化那一套留作后续）。
- **手机端不接 AI。** `packages/mobile` 这一轮只搭壳，AI 相关能力只在桌面端可用。
- **模型输出不干净时**（带「好的，这是优化后的提示词：」前缀、被包在 markdown 代码块里），程序会剥掉外壳；实在解析不出结构就把全文直接采用，并在界面上给一条「模型未按格式输出，已直接采用全文」的提示，原文照实展示、可重试。

## 能力边界（请按真实情况预期）

- **Win10 上的「毛玻璃」是窗口内模糊，不是系统级 acrylic。** 助手进程调 DWM 把面板背后的桌面真正模糊掉；助手不可用（被杀毒软件拦、编译失败、被改名）时自动降级为半透明 + 内部阴影，设置页会显示「已降级」，不会假装成功。
- **自动粘贴在提权窗口会失效。** UIPI 是系统限制，不是 bug。此时回退为「已复制，按 Ctrl+V 粘贴」的提示，不静默失败。
- **手机端这一轮只搭壳。** `packages/mobile` 能构建出在 Capacitor WebView 里跑的 Web 包，但**没有 APK**（本机没装 JDK / Android SDK / Gradle），也没有持久化（记录在内存里，进程杀掉即清空）。Android 10 起后台读剪贴板被系统禁止，所以手机端的产品形态是「手动粘进来 + 手动复制出去」，`backgroundCapture` 恒为 `false`。
- **文件记录只记路径，不复制内容。** 原文件被移动或删除后，粘贴会如实提示「文件已不在原位置」。文件列表的读取与写回走原生助手（Electron 的剪贴板接口读写不了标准 `CF_HDROP`，见上文「为什么文件走原生助手」）。
- **拼音搜索是预建索引列，不是 FTS5。** 搜的是「写进索引那一刻」的内容，改不了历史记录的索引；拼音对多音字只取一个读音（`pinyin-pro` 的默认读音）。
- **来源应用只记 exe 名**（如 `Code.exe`、`msedge.exe`），不记窗口标题、不记路径。取不到时留空，界面上就不显示来源，不会写「未知」这类假值。从面板里粘贴回写的内容不会把 Clipchan 自己记成来源。
- **语法高亮的语言是猜的**，不是让用户选：猜不出来就不高亮（显示成普通文本），混合语言的片段可能只认主语言。搜索时只有搜索词高亮，语法高亮让位。
- **回收站不参与搜索、分类、词云**，它只是一个按删除时间倒序的分页列表。清空回收站不可撤销（硬删）。
- **AI 优化用你自备的 Key，Key 以明文存放在本地 `clipchan.db`，本轮不做加密。** 只在桌面端可用，手机端不接 AI；详见上文「AI 提示词优化」。

pnpm install      # pnpm 11 的构建脚本许可写在 pnpm-workspace.yaml 的 allowBuilds 里；老版本 pnpm 才需要 --allow-build=electron --allow-build=esbuild --allow-build=better-sqlite3
